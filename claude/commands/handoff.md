# Handoff

## 目的

コンテキストをリセット（`/clear`）する前に、次のセッションが作業を再開するために必要な情報を
ファイルへ残す。会話への出力だけでは `/clear` で消えるため、必ずファイルへ永続化する。

## 引き継ぎファイルの場所

- パス: `<git リポジトリのルート>/.claude/plans/handoff-<ブランチ名>.md`
  - ブランチ名の `/` は `-` に置換する（例: `feature/foo` → `handoff-feature-foo.md`）
- ブランチ単位にする理由: worktree ベース開発では「ブランチ＝作業単位」であり、
  `/clear` 後に SessionStart hook がブランチ名から一意にファイルを引けるようにするため
- ファイルが無ければ新規作成、あれば更新する

## 情報の所在（重複させないこと）

引き継ぎファイルに、設計内容や進捗の値を**書き写さない**。参照先を指すだけにする。
値をコピーすると、片方だけ更新されて食い違う（ドリフト）。

| 情報 | 所有者 |
|---|---|
| 設計・技術方式 | `docs/design-doc/` の設計書 |
| 実装ステップの定義と進捗 | `.claude/plans/` の実装計画（チェックボックス） |
| 上記への参照・環境の状態・試行錯誤の記録 | 引き継ぎファイル |

例外: 実装計画が存在しない軽い作業の場合に限り、引き継ぎファイルの「現在の状態」へ
残作業を直接書いてよい。

## 手順（厳守）

1. `git rev-parse --show-toplevel` と `git branch --show-current` で、引き継ぎファイルのパスを決める
2. 今回の作業に対応する設計書（`docs/design-doc/`）・実装計画（`.claude/plans/`）のパスを特定する
3. 実装計画が存在する場合は、そのチェックボックスを現状に合わせて更新する
   - 進捗の所有者は実装計画であり、引き継ぎファイルではない
4. `git status` で未コミット変更の有無を確認する
5. `date '+%Y-%m-%d %H:%M'` で現在時刻を取得する（履歴の見出しに使う）
6. 下記テンプレートに従って引き継ぎファイルを書く
   - `## 現在の状態` は毎回**上書き**する
     （引き継ぎとは「今どこにいるか」であり、常に1つしか存在しない。複数並ぶと次のセッションが
     どれを信じるべきか判断できなくなる）
   - `## 履歴` は末尾へ**追記**する（過去のエントリは消さない）
7. オーナーへ次を報告する
   - 引き継ぎファイルのパス
   - 続けて `/clear` → `/resume-work` の順に実行するよう促す
     - `/clear` はビルトインコマンドであり Claude からは実行できない
     - `/resume-work` が必要な理由: `/clear` 後に走る SessionStart hook が渡せるのは背景情報で
       あって指示ではないため、Claude は自分から作業を再開しない。再開の起点を明示的な
       コマンドに一本化することで、毎回同じ手順で確実に再開できる

## ファイル構成（テンプレート）

````markdown
# 引き継ぎ: <ブランチ名>

## 現在の状態

- 設計書: <パス / 無ければ「なし」>
- 実装計画: <パス / 無ければ「なし」>
  - 進捗はこの実装計画のチェックボックスが正。未チェックの最初の項目から再開する
- ブランチ: <ブランチ名>
- 未コミット変更: <あり（主なファイル名）/ なし>
- 環境の状態: <起動中の開発サーバ、投入済みのテストデータ等 / 無ければ「なし」>
- 次に着手すること: <1〜3行>

## 履歴

### <YYYY-MM-DD HH:MM>

- やったこと: <箇条書き>
- 試して駄目だった方法とその理由: <あれば記載。無ければ「なし」>
- 判断したことと、その根拠: <あれば記載>
````

「試して駄目だった方法とその理由」は、コンテキストリセットで最も失われやすく、
失うと次のセッションが同じ失敗を繰り返す情報のため、必ず残すこと。
