# Resume Work

## 目的

`/handoff` → `/clear` でコンテキストを破棄した直後に、前セッションの作業を再開する。

`/clear` 直後は SessionStart hook が引き継ぎファイルの存在を通知しているが、hook が渡せるのは
背景情報であって指示ではないため、Claude は自分から作業を始めない。本コマンドがその起点になる。

## 手順（厳守）

1. 引き継ぎファイルを特定して読む
   - パス: `<git rev-parse --show-toplevel>/.claude/plans/handoff-<ブランチ名の / を - に置換>.md`
   - ファイルが無い場合は、その旨をオーナーに伝えて停止する（推測で作業を始めない）
2. 引き継ぎファイルの `## 現在の状態` に挙げられている参照先を読む
   - 設計書（`docs/design-doc/`）: 技術方式を把握する
   - 実装計画（`.claude/plans/`）: **進捗の正はこのファイルのチェックボックス**。
     未チェックの最初の項目が次の作業になる
   - どちらも「なし」の場合は、引き継ぎファイルの「次に着手すること」に従う
3. `## 履歴` の直近1〜2エントリを読む
   - 特に「試して駄目だった方法とその理由」を確認し、同じ失敗を繰り返さないようにする
   - 全エントリは読まない（文脈を軽く保つというリセットの目的に反するため）
4. `git status` で作業ツリーの状態を確認し、引き継ぎファイルの記述と食い違いがないか照合する
   - 食い違う場合は、実際の作業ツリーを正とし、その旨をオーナーに報告する
5. オーナーへ次を報告してから、作業を再開する
   - 再開地点（実装計画のどの項目か）
   - 未コミット変更の有無
   - 引き継ぎ内容と実際の状態に食い違いがあればその内容

## 注意

- 引き継ぎ内容に不明点や矛盾がある場合は、推測で進めずオーナーに確認する
  （CLAUDE.md 基本原則「不明点がある場合には作業を一時停止して質問する」）
